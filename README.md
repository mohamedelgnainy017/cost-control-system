# نظام متابعة الاستهلاك والتكاليف

نظام محلي (Desktop / Web) لقراءة ملفات Excel الضخمة وتحويلها إلى قاعدة بيانات واحدة
مع تحليلات دقيقة للمخزون والمبيعات والربحية — بواجهة عربية.

---

## التشغيل

**الطريقة السهلة:** انقر مرتين على `run.bat`
— يشغّل الخادم ويفتح النافذة كتطبيق على `http://127.0.0.1:4310`

**الطريقة اليدوية:**

```
node src\server.js
```

متطلبات التشغيل:

- Node.js 22 أو أحدث
- خدمة **PostgreSQL** تعمل (تم الاختبار على PostgreSQL 18)
- `npm install` مرة واحدة لتثبيت المكتبات (`pg` و `xlsx`)

> إن توقفت خدمة PostgreSQL يطبع الخادم رسالة واضحة ويتوقف — أعد تشغيل الخدمة ثم أعد التشغيل.

## المستخدمون والصلاحيات

- **الدخول إلزامي**: كل مسارات `/api/*` محمية — 401 لغير المسجّل، و403 لغير ذي الصلاحية
  (دفاع في طبقتين: الواجهة تخفي الأزرار غير المسموحة، والخادم يرفضها هو الآخر).
- **أول تشغيل**: تسجيل الدخول `admin` / `admin123` — يجبرك النظام على تغيير كلمة المرور
  قبل متابعة العمل (`must_change`).
- الإدارة من زر **👥 المستخدمون**: إضافة مستخدم، تغيير الدور، تعطيله، أو إعادة ضبطه
  إلى كلمة مرور مؤقتة تُطلب تغييرها عند أول دخول.

| الدور | الصلاحيات (`perms`) |
|---|---|
| `admin` — مدير | `import` استيراد • `sync` جلب البورصة والتعديل اليدوي • `users` إدارة المستخدمين • `master` تعديل البيانات الأساسية |
| `accountant` — محاسب | `import` • `sync` • `master` — **دون** إدارة المستخدمين |
| `viewer` — مشاهد | قراءة فقط: كل الشاشات والتقارير، **صفر** صلاحيات تعديل |

### صلاحيات الشاشات (على مستوى الشاشة)

إلى جانب صلاحيات الأزرار (`perms`)، يضبط المدير **أي شاشة يراها كل دور** من
لوحة التحكم ← بطاقة «🔐 صلاحيات الشاشات» (جدول شاشة × أدوار):

- تُخزَّن في إعداد `tab_perms` — الافتراضي (12 شاشة): **لوحة التحكم للمدير فقط**، والمحاسب 11 شاشة، والمشاهد 11 شاشة (كلها عدا لوحة التحكم)
- **الاستيراد ليس شاشة**: أُزيل تبويب «الاستيراد» العام؛ الاستيراد اليومي والإدخال اليدوي محميان بصلاحية الأزرار `import` (لا شاشة لها) عبر `PERM_ROUTES`
- المنع **في طبقتين**: الشاشة تختفي من قائمة المستخدم، **والخادم يرفض** مسارات بياناتها
  (403 برسالة «دورك لا يملك صلاحية شاشة …») — المسارات الشائكة (`overview`/`tables`/`health`/`span`) مشمولة عمداً
- الدرجة الأعلى تبقى للأزرار: حتى لو الشاشة مسموحة، زر التعديل يتطلب الصلاحية نفسها (`PERM_ROUTES`)

- مسارات الصلاحيات معرَّفة في `src/route-policy.js` (`WRITE_PERM_ROUTES` / `TAB_API`) ويستهلكها `src/server.js`، والأدوار في `src/auth.js` (`ROLES`). كل مسار كتابة له صلاحية صريحة، والتحقق على الخادم لا يعتمد على إخفاء الأزرار.
- المصادقة بكوكي جلسة `HttpOnly` محفوظ في جدول `sessions` (**7 أيام** — `SESSION_DAYS` في
  `src/auth.js`)، وكلمات المرور مخزّنة بـ **salt + hash** (بدون نص صريح).

## الوحدات

| الوحدة | الوظيفة |
|---|---|
| 📊 لوحة التحكم | **إدارة المستخدمين والصلاحيات فقط** (شاشة خاصة بالمدير): بطاقة المستخدمون (إضافة/تعطيل/أدوار/إعادة تعيين) + بطاقة صلاحيات الشاشات (جدول شاشة × أدوار) — دون أي محتوى تحليلي أو تشغيلي آخر |
| 🧱 الأصناف الأساسية | جدول `items` **الواحد** للصنف وبياناته (التسلسل: التصنيف ← مجموعة المواد ← الصنف)، والمجموعات والتصنيفات صفوف داخل نفس الجدول بنوع `kind` (`'group'`/`'class'`). في نموذج الصنف تُ**ختار** المجموعة والتصنيف من قائمتين (كل خيار «كود — اسم»)، مع زري «＋ مجموعة» و«＋ تصنيف» للإضافة والتعديل — **تُدار يدوياً من النظام فقط** (لا استيراد تلقائي مع الحركات)؛ ولجلب الأصناف/الوحدات/مواقع التخزين الجديدة من الحركات عند الحاجة زر **↻ جلب من الحركات** (perm: master) |
| 🏭 المواقع والمصانع | التسلسل **الشركة ← الوحدة ← المخزن**: الشركة (كود + اسم + عملة) تعدّل مرة واحدة فتتبدّل وحداتها، الوحدة (كود + اسم + شركة + مكان)، المخزن (كود + اسم) يُسند عليه الشركة والوحدة والمكان تلقائياً |
| ⇅ أنواع الحركات | نوع الحركة ووصفه (البيانات الحالية) + **وصف السيستم والتصنيف** — حركة واحدة قد تُصنَّف لبند آخر بناءً على وصف السيستم |
| 📦 المخزون والمطابقة | افتتاحي + حركات = ختامي لكل مفتاح، فروقات، توزيع المخزون |
| 🧾 المبيعات والربحية | **ثلاثة تقارير فقط** في **شاشة التقارير (مجموعة «تقارير مبيعات»)** — (١) **تفصيلي** بكل الأبعاد (صنف/وحدة قياس/تصنيف/مجموعة/مخزن/وحدة/مكان/شركة/عملة) مع قيمة البيع وتكلفته ومجمل الربح، (٢) **إجمالي** باختيار «طريقة إظهار التقرير» (صنف • مكان • شركة • عميل • مخزن) — ومستويات المجموعة (مكان/شركة/عميل/مخزن) **مفصّلة على مستوى الصنف** (مجموعة × صنف) لإعطاء دلالة فعلية، مع قائمة «طريقة ربط التكلفة»، (٣) **فترات** بالأعوام ثم الأشهر — والتكلفة مربوطة بالمبيعات عبر المستند المرجع + الصنف. أما **شاشة المبيعات اليومية** فتعرض **تقريراً تفصيلياً واحداً** بـ«طريقة تجميع» (تفصيلي بكل الأبعاد • صنف • مكان • شركة • عميل • مخزن — ومستويات المجموعة مفصّلة بالأصناف) مع **قيمة البيع والكمية وقيمة البيع للوحدة** — **دون أي بنود خاصة بالتكلفة** (لا تكلفة/ربح/هامش/ضريبة) ولا كروت مؤشرات |
| 🔄 الحركات | **تقرير واحد**: صنف × وحدة × توجيه × مخزن × مكان (كمية/قيمة) + تجميع كل توجيه — بأرقام صافية بعد إسقاط حركات الإلغاء |
| ⇄ تقارير المخازن (مركز التقارير) | **ثلاثة تقارير** بمنطق تقارير المبيعات: (١) **تفصيلي** بكل الأبعاد (تاريخ • صنف • وحدة قياس • توجيه • مخزن • مكان • وحدة • شركة • نوع حركة) مع وارد/صادر/صادر الكمية والقيمة، (٢) **إجمالي** بـ«بند التجميع» (صنف • مكان • شركة • مخزن • وحدة • توجيه • نوع حركة) — ومستويات المجموعة **مفصّلة على مستوى الصنف** (مجموعة × صنف)، (٣) **فترات** بالأعوام ثم الأشهر — وكلها بأرقام صافية بعد إسقاط حركات الإلغاء (نفس أرقام شاشة الحركات تماماً) |
| ◫ تقارير الأرصدة (مركز التقارير) | **ثلاثة تقارير**: (١) **تفصيلي** بكل الأبعاد (تاريخ • صنف • وحدة قياس • وحدة • مخزن • مكان • شركة • تصنيف • مجموعة) مع الافتتاحي والختامي وحركة اليوم، (٢) **إجمالي** بـ«بند التجميع» (صنف • مكان • شركة • مخزن • وحدة • تصنيف • مجموعة) مفصّلة على الصنف (سجلات/أيام/افتتاحي/ختامي)، (٣) **فترات** بالأعوام ثم الأشهر — الرصيد الافتتاحي في **أول** تاريخ بالفترة والختامي في **آخر** تاريخ بها |
| ⌁ البورصة اليومية | أسعار الذرة/الصويا/البذرة + ريت الدولار **بجلب ذاتي يومي** (Yahoo + بنك مصر) + تعديل يدوي مؤرخ + **إدخال يدوي** لصف التكييف |
| 💲 الأسعار اليومية | 4 قيم لكل صنف/يوم (تكلفة/سوق × بر/ولاصة) مع تعديل مؤرخ وسجل إلغاء + **إدخال يدوي** |
| 🧮 التكلفة اليومية | محرك احتساب التكلفة اليومية (شبك صنف×مصنع أو الإجماليات) + تحذيرات + إعادة بناء كاملة |
| ⚠️ جودة البيانات | **13 فحصاً** آلياً (تكرارات، أصناف ناقصة، أرصدة سالبة، عملات، استمرارية الأرصدة، ...) |
| 📥 البيانات اليومية | **لا تصفّح مجلدات ولا مسارات ملفات**: البيانات اليومية تدخل بالكامل من الشاشات اليومية — زر **«⬆ استيراد البيانات»** (رفع ملف ← **معاينة الجداول والصفوف** ← تأكيد التعديل/الاستبدال/الحذف/البحث) أو زر **«＋ إدخال يدوي»** لإضافة/تعديل/حذف حركة أو فاتورة بيع أو رصيد مباشرةً. أما بيانات المراجع (الأصناف/المواقع/أنواع الحركات) فتُدار يدوياً من النظام |
| 📁 التقارير | **مركز تقارير**: 16 تقريراً تُعرض داخل المتصفح (جدول + رسم) ثم تُصدَّر CSV — ثلاثة «إجمالي» (مبيعات/حركات/أرصدة) عناصر واجهة ببند تجزئة، والتقارير التي حلّت محلها الثلاثيات الجديدة ما زالت متاحة للتصدير |

## ربط تكلفة المبيعات (الربحية)

تكلفة المبيعات تُشتق من **حركات المخزون** (قاعدة `cost_rule`: مؤشر الحركة `L` أو التوجيه
«صادر»)، ثم تُنسب إلى بنود المبيعات بإحدى طريقتين يتحكم بهما إعداد **`cost_link`**:

| الطريقة | الربط | ملاحظة |
|---|---|---|
| `doc_item` **(الافتراضي)** | `المستند المرجع + الصنف` ← `مرجع الحركة + الصنف` | الأدقّ: تكلفة كل بند من حركات مستنده نفسه |
| `place` | تجميع حركات التكلفة **حسب المكان** | الطريقة القديمة — للمقارنة |

- **مجمل الربح = الإيراد − تكلفة المبيعات**، والهامش % = الربح ÷ الإيراد.
- **لا تكرار ولا فقدان**: لو تكرر نفس (المستند المرجع + الصنف) في أكثر من بند مبيعات،
  تُوزَّع تكلفة الحركة عليهم بالتساوي.
- **نسبة التغطية**: بند مبيعات بلا حركة مقابلة تكلفته = صفر، وتُعرض في الشاشة **نسبة البنود
  والقيمة المطابقة فعلاً** حتى يظهر حجم غير المطابق بوضوح.
- التبديل بين الطريقتين من **قائمة «طريقة ربط التكلفة»** داخل بطاقة **«إجمالي المبيعات والربحية»**
  في **مركز التقارير** (شاشة التقارير — مجموعة «تقارير مبيعات») (صلاحية `master`) أو عبر
  `POST /api/settings/cost`. تغيير الطريقة يُبطل كاش المؤشرات تلقائياً.
- **نقطة التوسّع المستقبلية**: كل منطق الربط محصور في `COST_LINKS` و`profitCte()`
  في `src/analytics.js` — أي تعديل قادم على احتساب التكلفة يُضاف هناك.

## البورصة اليومية — جلب ذاتي (بلا ارتباط بملف Excel)

**نقطة الانفصال:** النظام لا يقرأ ولا يكتب أي ملف بورصة. الأسعار تُجلب داخل النظام
وتُكتب مباشرة في جدول `borse` — بينما يبقى **الأرشيف** (5,223 سجلاً حتى 2026-10-07)
مستورَداً من الملف كما هو **دون أن يمسّه الجلب أبداً**.

### من أين تأتي الأرقام؟

| الحقل | المصدر | متى |
|---|---|---|
| منخفض / عالي / إغلاق لكل صنف | **Yahoo Finance** — سلسلة العقد الأمامي (`.CBT`) | كل جلب |
| ريت الدولار (`banknoteSell`) | صفحة **بنك مصر** الرسمية | كل جلب |
| العقد (مثلاً «26 ديسمبر») | مُشتق من العقد الأمامي المختار تلقائياً | كل جلب |
| البريم • سعر البورصة • النولون • المصاريف • المعامل • سعر التكلفة | **يُحمَّل للأمام** من آخر صف لنفس الصنف | عند إدراج يوم جديد |

- **المجدول**: يومياً الساعة **22:00** (بعد اكتمال جلسة البورصة الأمريكية 18:20 UTC) —
  يُغيَّر من إعداد `borse_fetch_time` (أو متغيّر البيئة `BORSE_FETCH_TIME`). عند الفشل
  تُعاد المحاولة كل 30 دقيقة، وعند إقلاع الخادم تُلتقط الأيام الفائتة فوراً (بعد 06:00)
  بسقف **60 يوماً**.
- زر **«⚡ جلب الآن»** يشغّل الجلب فوراً: يكتب صف اليوم (ويجدّده عند كل ضغطة حتى يستقر
  الإغلاق) ويضيف أي يوم ناقص — بلا أي كتابة في الملف.
- **حماية التاريخ**: صفوف الأيام السابقة لا يلمسها الجلب إطلاقاً (ولو انقطعت الحالة) —
  الاستثناء الوحيد صف **اليوم** لأنه لم يُغلَق بعد.
- **التمرير التلقائي للعقود**: عند انتهاء العقد أو توقف جلساته ينتقل النظام إلى أقرب
  عقد تسليم قادم له جلسة طازجة (≤4 أيام) ويحدّث عمود العقد مع أسعاره معاً —
  مثال: البذرة `ZSX26` «26 نوفمبر» ← تلقائياً «27 يناير» في أول شهر تسليمه.
- **العطلات**: لو لم توجد جلسة في يوم المطلوب تُعاد آخر جلسة خلال 7 أيام (نفس سلوك
  الورقة في الجمعة/السبت).
- **تقريب الإغلاق** مطابق للأداة: ذرة وبذرة `floor` (‎508.75 ← 508‎)، وصويا عشرية واحدة
  بتقريب نصف زوجي (‎357.25 ← 357.2‎).
- **حماية تاريخ صفحة البنك**: الصفحة تُظهر النشرة الحالية فقط — إن كان تاريخها أحدث من
  يوم الجلب نحتفظ بالقيمة المخزنة لذلك اليوم (أو نرجع لأقرب قيمة سابقة) فلا يُكتب رقم
  حديث على يوم قديم.
- سجل كل محاولة (وقت، أيام، عقود، ريت، أخطاء) في إعداد `borse_fetch_state` ويُعرض
  في أعلى تبويب البورصة. المصادر: `src/borse-fetch.js` (الجلب والمجدول) و
  `src/borse-edit.js` (التعديل المؤرخ).

### التعديل اليدوي (تبويب «✎ تعديل يدوي»)

- نقر أي خلية يفتح نافذة التعديل؛ الحقول السبعة: العقد، متوسط البريم، سعر البورصة،
  ريت الدولار، النولون، المصاريف، معامل التحويل
- **قاعدة السريان**: قيمة تعدَّلت في يوم تُطبَّق على كل الأيام بعده حتى تاريخ تعديل أحدث
  (تُخزَّن في `borse_overrides` كـ `eff_date` — لا يُمسّ تاريخ التعديل القديم)
- التعديل يظهر فوراً في الشبكة مع علامة `●` وقيمة الجلب الأساسية في تلميح الخلية،
  وتبويب «سجل التعديلات» يعرض كل تعديل مع زر **«↩ إلغاء»** (حذف السطر ← تعود الخلية
  إلى القيمة الأساسية).
- **التعديل يعلو الجلب دائماً**: الجلب يكتب «القيمة الأساسية» فقط، فلا يضيع تعديلك
  مهما اكتملت الأيام الجديدة — بل ينتقل تلقائياً إليها حتى تلغيه.
- **لا كتابة في الملف**: زرا «حفظ في ملف Excel» والحفظ التلقائي أُزيلا بالكامل، وكذلك
  جدول `borse_written` (يُحذف تلقائياً عند أول تشغيل).

## الانفصال عن ملف البورصة

النظام لم يعد **يقرأ ولا يكتب** `تسجيل حركات يومية.xlsx` — نقطة الانفصال مكتملة:

| العنصر القديم | المقابل الجديد |
|---|---|
| `POST /api/borse/sync` (استيراد شيت البورصة) | `POST /api/borse/fetch` (جلب من Yahoo + بنك مصر) |
| زر «تحديث من الملف اليومي» + تنبيه «يوجد تحديث جديد» | زر «⚡ جلب الآن» + حالة آخر جلب وأيامه |
| `POST /api/borse/write-file` (Excel COM) والحفظ التلقائي | أُزيل — لا كتابة في أي ملف |
| `POST /api/borse/file {path}` + إعداد `borse_file` | أُزيل — لا مسار ملف أصلاً |
| جدول `borse_written` (قيم أصلية للاسترجاع) | أُزيل (يُحذف تلقائياً) — الإلغاء يعود للقيمة الأساسية |
| خيار الاستيراد `--formatted` + `readSheetRaw` | أُزيل — تبقى القراءة `raw` فقط |
| `src/write-borse.js` + `src/write-borse-overrides.ps1` | حُذفا |
| قراءة `borse-tool\state\last-finalized.txt` (تنبيه) | أُزيل — الجلب يحمي التاريخ بنفسه |

**ما يبقى**: استيراد المبيعات/الحركات/الأرصدة من الملفات اليومية عبر الشاشات اليومية
(معاينة ← تأكيد)، والإدخال اليدوي للحركات/المبيعات/الأرصدة، وكامل التعديل المؤرخ فوق
القيم المجلوبة. لا تصفح مجلدات ولا مسارات ملفات.

**أداة `..\borse-tool`**: تبقى كما هي **دون أي تعديل** وتعمل على الملف بشكل مستقل
(لا نقرأ خرجاتها ولا نعتمد عليها) — إن أردت مسك الملف خارج النظام فهو مسار منفصل
لا علاقة له بالنظام.

## الاستيراد

- يقرأ **أي ملف Excel** (.xlsx / .xlsm / .xlsb / .csv)
- **الملفات المحمية بكلمة مرور** تُقرأ تلقائياً عبر برنامج Excel المفتوح على الجهاز
- **كشف تلقائي** للجداول بحسب عناوين الأعمدة (يتجاهل تقارير الـ Pivot):
  - دليل الأصناف، المواقع والشركات، أنواع الحركات
  - حركات المخزون، المبيعات، أرصدة المخزون
  - (أسعار البورصة **ليست من الملف** — تُجلب ذاتياً، انظر أعلاه)
- يتكبّت التباين الشائع في الكتابة العربية (ى/ي، ة/ه) ويتعرّف على **الملفات اليومية الفعلية**:
  - **المبيعات**: `تاريخ الفاتورة` • `كمية الفاتوره` • `صافى القيمه " الفاتورة "` • `المستند المرجع`
    • `كود الصنف`/`اسم الصنف` • `الوحده`/`الوحدة` • `رمز الشركة` (بدون الحاجة لعمودي الفئة/الحالة — تُعتبر كل الصفوف مبيعات موجبة)
  - **الأرصدة**: `رمز الشركة` • `الوحدة` • `موقع التخزين` • `المادة`/`وصف المادة` • `نوع المادة`
    • `كمية المخزون في بداية الفترة` / `في نهاية الفترة` — وبلا عمود تاريخ: **يُؤخذ تاريخ اليوم من اسم الملف** (`01-09-2026.xlsx`)
- كل صف يحمل `source_file` — استيراد ملف يستبدل بيانات **نفس الملف فقط**
  (تعدد المصادر: ربط ملفات/شيتات جديدة دون مسح القديم)
- بعد كل استيراد تُشتق الحقول: **المكان** (من جدول المواقع) و**توجيه الحركة**
- استيراد محدود بجدول أو أكثر محدَّد: `--only=sales,movements` (معاينة: `--preview`)

### استيراد البيانات اليومية (داخل الشاشات اليومية)
- في **حركات سيستم يومية** و**مبيعات يومية** و**أرصدة يومية** زر **«⬆ استيراد البيانات»**
  يفتح مديراً للملفات اليومية: **＋ إضافة ملف** (رفع من المتصفح مباشرة)، **استبدال**
  أي ملف قائم، **حذف** ملف (تُمسح صفوفه من الجداول)، و**بحث** بالاسم أو التاريخ.
- عند اختيار ملف تظهر **معاينة قبل الاستيراد** داخل النافذة نفسها: الشيتات والجداول
  المكتشفة مع عناوين الأعمدة وعيّنة من الصفوف — ثم **تأكيد** أو **إلغاء**. للملفات
  المحمية بكلمة مرور، أدخلها في المعاينة (تُعاد تلقائياً) أو عند التأكيد.
- الملف يُحفظ باسمه — عادةً **تاريخ اليوم** (`01-10-2026.xlsx`) في `data/uploads/<الفئة>`
  (الحركات/المبيعات/الأرصدة). **رفع الاسم نفسه مرة أخرى يستبدل الملف والبيانات القديمة
  بالجديدة** تلقائياً — حتى لو غيّرت محتواه. والاستبدال من قائمة «استبدال» يعيد استخدام
  هوية الملف القديم فلا تتكرر صفوفه.
- الرفع يشغّل استيراداً بنفس شريط التقدّم ثم يُحدَّث الجدول وعدّادات الرأس والسجل فوراً.

### الإدخال اليدوي (حركات/مبيعات/أرصدة/بورصة/أسعار)
- بجوار كل زر استيراد زر **«＋ إدخال يدوي»** يفتح نموذجاً لإضافة/تعديل/حذف صف واحد، وكذلك في
  شاشتَي **البورصة اليومية** و**الأسعار اليومية** (كلتاهما بلا ملف مصدر — إدخالهما يدوي).
- يُخزَّن الصف بوسم `source_file='manual'`، و**التعديل/الحذف مقتصران على الصفوف اليدوية
  فقط** — صفوف الملفات المستوردة محصّنة من هذه الشاشة.
- تُشتق الحقول المعتمدة لحظة الحفظ: **المكان** و**الشركة** (من جدول المواقع)،
  و**توجيه الحركة** (من أنواع الحركات)، و**إشارة البيع** (كمية/قيمة موجبة).
- **البورصة**: صف (تاريخ × صنف) بقيم السوق ومدخلات التكلفة، و**سعر التكلفة يحسبه النظام**
  بنفس معادلة شاشة التعديل — `(السعر + البريم) × معامل التحويل × الريت + المصاريف`.
  وصف البورصة اليدوي **لا يمسّه الجلب الذاتي** أبداً («التعديل يعلو الجلب»).
- **الأسعار**: صف (تاريخ × صنف) بقيمتي التكلفة/السوق (يعمل `num` على الفواصل والأرقام العربية،
  والقيمة غير الرقمية تُفهم «لا قيمة»).
- حفظ أو حذف صف **بورصة/أرصدة** يدوي يُعيد بناء **محرك التكلفة اليومية** من تاريخ الصف تلقائياً.

### تقرير حركات السيستم (شاشة «حركات سيستم يومية»)

شاشة الحركات لم تبقَ فيها تقارير ولا كاردز متفرّقة — **تقرير واحد** بتجميع التوجيه فوقه:

- **المواصفات**: (صنف × وحدة × توجيه × مخزن × مكان) ← الكمية والقيمة الصافية.
- **تعامله مع اصطلاح السيستم**: كل حركة **إضافة موجبة** وكل حركة **صرف سالبة** — ولا
  يوجد حذف في السيستم، فإلغاء أي حركة يظهر كـ**حركة تالية بعكس الإشارة** وقيمة مطابقة.
  التقرير يُسقط تلك الأزواج (نفس المفتاح ونفس |الكمية| و|القيمة| بإشارتين معاكستين)
  فلا تتضخّم الأرقام ولا العدد — ثم يعرض **وارد/صادر منفصلين** والصافي لكل توجيه.
- **أثر الإسقاط** في بيانات اليوم الحقيقية: 58,482 صف خام ← **4,867 زوج إلغاء**
  (9,734 صف) ← **48,748 حركة حقيقية**؛ صفوف «جودة» كانت كلها إلغاءات فأصبحت صفراً.
  أما مجاميع القيمة فلا تتغير لأن طرفي الزوج يلغي أحدهما الآخر.
- المبدأ (الجدول `live` داخل `analytics.js`) لا يمسّ تقارير المخزون والمطابقة —
  فهي تقرأ الحركات بالمدى لا بعددها، والمطابقة لا تتأثر بالصفوف الملغاة.

## قاعدة البيانات

- **PostgreSQL** — قاعدة `costcontrol` (تُنشأ تلقائياً عند أول تشغيل: `CREATE DATABASE costcontrol`)
- الاتصال محفوظ في `data/config.json` (محلي — لا يُرفع مع الكود):

```json
{ "host": "127.0.0.1", "port": 5432, "user": "postgres", "password": "••••", "database": "costcontrol" }
```

- يمكن تجاوزه بمتغيرات البيئة: `PGHOST` `PGPORT` `PGUSER` `PGPASSWORD` `PGDATABASE`
- **النسخ الاحتياطي:** `pg_dump -U postgres -Fc costcontrol > backup.dump`
- عند الرفع لاحقاً على سيرفر: غيّر بيانات الاتصال في `config.json` فقط

### متغيرات التحليل الاختيارية

- **`WORKFLOW_WORKBOOK_DIR` — مصادر Excel للقراءة فقط:** مسار مطلق لمجلد مصرّح به. لا يُفعَّل أي ملف Excel بدونه؛ تظهر في الواجهة رسالة عربية توضّح أنه غير مهيأ. يُقرأ فقط `.xlsx` و`.xlsm` و`.xlsb` و`.xls` بأسماء ملفات مباشرة (بلا مسارات فرعية أو `..`)، مع منع الخروج من المجلد، ويتطلب صلاحية `import`. لا يكتب التطبيق أي ملف في هذا المجلد. يعرض `GET /api/datasets/workbooks/diagnostics` تشخيصاً وصفياً (حالة الإعداد، الملفات، الأوراق، الأبعاد، الاقتطاع) بلا إرجاع صفوف أو قيم.
- **`WORKFLOW_PYTHON_NODE` — عقدة Python المقيّدة:** تتاح تلقائياً عند وجود Python 3 و`python/workflow_transform.py`. أوقفها صراحةً بالقيمة `0`. ليست تنفيذ Python حرّاً: عمليات بيضاء معلنة فقط، بلا كود أو استيراد أو ملفات أو شبكة، وبحدود للصفوف والعمليات والمهلة وحجم الناتج.
- **التحقق الفعلي من المعادلات:** `POST /api/formulas/verify` ينفّذ المعادلة على عيّنة صفوف (حد أقصى 1000) ويعيد `verified` / `not-numeric` / `empty` / `failed` مع الاعتماديات والقيم. لا يكتفي بفحص الصياغة.
- **تصدير PDF:** يستخدم طباعة المتصفح («حفظ كـ PDF») بنفس بيانات التقرير عند غياب حزم PDF العربية على الخادم. لا تُثبّت حزم إضافية لهذا الغرض. تصدير Excel يعمل من الخادم (`/api/reports/export/xlsx`).

### الجداول

`items` (الأصناف — **الجدول الواحد**: صف الصنف مع `origin`: `mine` مسجّل يدوياً/بالملف أو `movement`
مُجلب من الحركات، وأعمدة `class_*` التصنيف و`group_*` مجموعة المواد — والمجموعات والتصنيفات نفسها
صفوف داخل الجدول بنوع `kind`: `'group'` أو `'class'` تملآن قائمتي اختيار المجموعة والتصنيف في نموذج
الصنف وتديرهما زرا «＋ مجموعة» و«＋ تصنيف» — التسلسل كله داخل الجدول الواحد) •
`locations` (الوحدات والشركات) •
`companies` (سجل الشركات: كود + اسم + عملة) • `warehouses` (المخازن: كود + اسم + شركة + وحدة + مكان) •
`movement_types` (أنواع الحركات — مع `system_desc` وصف السيستم و`category` التصنيف) •
`movements` (الحركات) • `sales` (المبيعات) • `balances` (الأرصدة) • `borse` (البورصة: أرشيف
مستورد + صفوف الجلب الذاتي، عمود `source_file` يفرّقهما) • `borse_overrides` (التعديلات المؤرخة) •
`prices` (الأسعار اليومية) • `price_overrides` (تعديلات الأسعار المؤرخة) • `daily_costs`
(التكلفة اليومية — مع عرض `daily_costs_total` للإجماليات) •
`imports` (سجل الاستيراد) • `quality_issues` (ملاحظات الجودة) • `recon` (المطابقة) •
`sessions` • `users` • `settings` (فيها حالة الجلب `borse_fetch_state` وموعده `borse_fetch_time`)

كل جدول بيانات يحمل `source_file` — استيراد ملف جديد يستبدل بيانات **نفس الملف فقط**،
وهذا ما يسمح لاحقاً بربط ملفات/شيتات إضافية معاً دون مسح بعضها.

## الرفع على سيرفر أونلاين لاحقاً

1. ارفع المجلد كما هو على السيرفر (Linux/Windows) الذي عليه Node 22+
2. أنشئ قاعدة بيانات وحدّث `data/config.json`
3. شغّل `PORT=80 node src/server.js`

> ملاحظة: لا تصفّح مجلدات ولا مسارات ملفات إطلاقاً — الملفات تُرفع من المتصفح
> مباشرةً إلى `data/uploads/<الفئة>` عبر نوافذ الاستيراد اليومي، أو تُدخل الصفوف يدوياً.
