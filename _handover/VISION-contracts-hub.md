# رؤية إعادة الهيكلة — «مركز ذكاء عقود الاستيراد»

> مستند دراسة وتخطيط — أُعِدَّ بعد فحص كامل: قاعدة البيانات الفعلية، ملف `عقود الاستيراد.xlsm` (11 ورقة)، ملف `pbix_ready2.pbix` (7 صفحات / 60 عنصر مرئي)، `ملخص حركة بيع وتكلفة السيستم.xlsx` (مصدر الأصناف)، وكود الخادم/الواجهة.
> **لا تغييرات على الكود بعد** — هذا المستند للاعتماد قبل التنفيذ.

---

## 1) الملخص التنفيذي

النظام الحالي **يعمل** لكنه يعرض **شريحة صغيرة** من البيانات المتاحة:

- تقارير عقود الاستيراد (10 تقارير PBIX) = إعادة بناء أمينة لصفحات PBIX السبع، لكنها **تتجاهل 4 أوراق كاملة** في ملف الإكسل: `التحميل` (1116 سطر)، `الرول` (38)، `الافراج` (63)، وورقات المتابعة المحسوبة (`متابعة الربط`، `متابعة التحميل`).
- الربط بين جداول العقود وبين بيانات النظام العام (`items`) **يجري بالاسم المُطبَّع** (`clsKey`) — هشّ. بينما توجد **قناة ربط دقيقة بالكود** غير مستغلة: `items.group_code` = `contract_items.code` = `contract_balances.item_code` (‎1001..5002‎).
- عمود «ما تم بيعه» = **صفر دائماً** (جدول `contract_external_sales` فارغ).
- فصل «خامات رئيسية / إضافات» يجري بقاعدة تخمينية (بادئة الكود `[24]` أو تعبير اسمي) بدل الحقل الحقيقي `items.class_code` (`101=خامات`، `102=إضافات`، `204=خامات معبأ`...).
- فلاتر مركز التقارير عامة (تاريخ/مكان/وحدة/مخزن...) **لا تناسب العقود** (مورد/مصدر/تصنيف/مركب/موقف).

**الرؤية:** توحيد كل شيء على **محور تصنيف واحد بالكود**، واستغلال **كل الأوراق والجداول**، وجمع العشرة تقارير في **«مركز ذكاء عقود الاستيراد»** واحد بتبويبات داخلية وفلاتر موحّدة وتتبّع تفصيلي (Drilldown) من الرقم الداخلي.

### 2.3 🎯 الجسر الحقيقي المكتشف (أهم نتيجة)

جدول `items` العام يقسّم أصنافه بمفتاح `group_code` الذي **يطابق حرفياً** أكواد `contract_items` وأكواد `contract_balances`:

```
items.code (9 خانات)        111000001   "ذره صب مستورد"
  └─ group_code  = 1001  ◄──────────►  contract_items.code  = 1001  "الــــــــــذرة"
  └─ group_desc  = "الــــــــــذرة"     contract_balances.item_code = 1001
  └─ class_code  = 101 "خامات"
```

| المحور | القيم |
|---|---|
| `items.group_code` | `1001..1033`, `2001..2027`, `3001..3007`, `4002..4005`, `5001..5009`, `6001` (+ أكواد `C*/D*/G*/K*/R*/T*/Z*`) |
| `contract_items.code` | `1001..1033`, `2001..2027`, `3001..3007`, `4002..4005`, `5001..5002` ← **مجموعة جزئية** |
| `contract_balances.item_code` | `1001..` نفس الفضاء |

**الخلاصة:** الربط الصحيح = **بالكود** (`classification` → `contract_items.code` → `items.group_code`)، لا بالتطبيع النصي. وهذا يفتح الطريق لتصنيف صحيح وربط بكل أصناف النظام.

## 3) الرؤية المقترحة (To-Be)

### 3.1 الفلسفة

> **«بيانات واحدة، محور واحد، تجربة واحدة.»**
> ملف `بيانات` هو **المصدر الأوحد للحقيقة** (Single Source of Truth): منه يُبنى محور الأصناف والتصنيفات، وكل القوائم المرجعية (مورد/ميناء/مصدر/شركة/أنواع/مواقف). وكل ما بعد ذلك يُربط **بالكود**، ثم يُعرض في **مركز واحد**.

### 3.2 المحور الموحَّد (Canonical Spine)

بناء جدول أبعاد واحد: **`v_class` / `dim_class`** مفتاحه `class_code` = نفس أكواد `1001..5002`، ويجمع:

| الحقل | المصدر |
|---|---|
| `class_code` | `contract_items.code` = `items.group_code` |
| `class_name` | `contract_items.name` = `items.group_desc` |
| `direction` | `contract_items.direction` (خامات/إضافات/أخرى) |
| `kind` | من `items.class_code` (101 خامات = **main**، 102 إضافات = **additive**، 204 خامات معبأ...) |
| `lot`, `factor` | `contract_items.lot/factor` |
| `erp_items` | عدد أصناف النظام المرتبطة (`items` حيث `group_code=class_code`) |

**قواعد الربط الصارمة الجديدة:**
1. كل جدول عقود ← `internal_no` (كما هو).
2. كل تصنيف (اسم) ← يُحلّ إلى `class_code` عبر `contract_items` (اسم→كود)، مع fallback إلى `items.group_desc`، ثم التطبيع النصي كحل أخير.
3. كل صنف نظام ← `items.group_code` ← `class_code`.
4. مفتاح `item_code` في الأرصدة ← `class_code` مباشرة.

### 3.3 استغلال كل الأوراق — التحليلات الجديدة

| الورقة/الجدول | تحليل جديد مقترح |
|---|---|
| `التحميل` (1116) | **متابعة التحميل**: متعاقد عليه مقابل مُحمَّل فعلياً، تقدّم التحميل %، تحميل مركب/مخزن، تسلسل زمني للتحميل، الكمية المتبقية للتحميل |
| `الرول` (38) | **أثر الترويل**: بورصة التعاقد/الربط/الرولينج وسعر الرولينج، أثر الترويل على التكلفة |
| `الافراج` (63) | **متابعة الافراج**: مُحمَّل مقابل مُفرَغ، مخزن/مركب، نسبة الافراج |
| `السداد` (206) | **متابعة السداد**: داخلي/خارجي/فروق تسعير، مبدئي/نهائي، المدفوع مقابل المتبقي، شركة السداد |
| `الربط` (363) | **الربط مقابل التسعير** (مُحسّن بالكود) |
| `متابعة الربط` + `متابعة التحميل` | مقارنة النظام بالورقتين المحسوبتين (Reconciliation) |
| `بيانات` مراجع | **قاموس موحّد** لكل القوائم: مورد، ميناء، مصدر، شركة، نوع السداد/السعر/التحميل/الافراج، موقف العقد/المركب/السداد، نظام الشحن، جهة التحميل |

### 3.4 «مركز ذكاء عقود الاستيراد» — الواجهة الجديدة

**بنية التنقّل المقترحة** (تبويب واحد «عقود الاستيراد» بمستويين):

```
📄 عقود الاستيراد  ▾
 ├─ خطوات العقد (إدخال/مراجعة)   [كما هو — 7 خطوات]
 ├─ 📊 لوحة المتابعة الذكية        ← جديد
 │   ├─ نظرة عامة (KPIs)
 │   ├─ موقف الربط والتسعير
 │   ├─ متابعة التحميل            ← جديد (ورقة التحميل)
 │   ├─ متابعة الافراج             ← جديد
 │   ├─ متابعة السداد              ← جديد (مفصّل)
 │   ├─ تكلفة الخامات المسعرة
 │   ├─ تغطية خامات رئيسية
 │   └─ تغطية الإضافات
 └─ 📄 التقارير الخام (13 جدولاً)
```

**داخل اللوحة الذكية:**
- **شريط KPIs مترابط** أعلى الشاشة: تعاقد / ربط / مدفوع / مُحمَّل / مُفرَغ / رصيد / أيام التغطية / قيمة المطلوب سداده.
- **شريط فلاتر موحّد بأبعاد العقود الحقيقية:** المورد • المصدر • التصنيف • نوع التعاقد • الشحن • موقف العقد • المركب • الميناء • فترة (من/إلى).
- **بطاقة تتبّع (Drilldown)** واحدة: بالنقر على أي تصنيف/عقد (`internal_no`) تُفتح بطاقة تجمع **كل مراحله**: التسجيل → التفصيل/المركب → التحميل → الربط → الرول → الافراج → السداد → الأرصدة.
- ربط مباشر بـ **النظام العام**: زر «أصناف هذا التصنيف» يفتح أصناف `items` المرتبطة بالكود.

### 3.5 معمارية البيانات المستهدفة (ERD مبسّط)

```
                 ┌──────────────────────────┐
                 │  dim_class (class_code)  │  ← المحور الموحّد (1001..5002)
                 │  name, direction, kind   │
                 └────────────┬─────────────┘
                              │ class_code
        ┌─────────────────────┼───────────────────────────┐
        │                     │                           │
   items (group_code)   contract_registrations      contract_balances
        │                (classification→code)        (item_code)
        │                     │
        │             contract_details / loading / hedge / roll / release / payments
        │                     │
        └──────────►  كلها بمفتاح internal_no + class_code
```

## 7) سجل التنفيذ

### ✅ المرحلة 1 — توحيد المحور بالكود + إصلاح التصنيف (منجزة ومُتحقَّق منها)

**ما نُفِّذ في `src/analytics.js`:**

- أُضيفت حقول `class_code` و`class_desc` و`direction` إلى صفوف التغطية.
