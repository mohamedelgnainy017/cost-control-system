# دراسة البيانات الشاملة — تطبيق ضبط التكاليف (Cost Control)

> مستند دراسة مبنية على **فحص فعلي مباشر لقاعدة البيانات الحقيقية** (`costcontrol` — PostgreSQL 18.6) بتاريخ 2026-10-17.
> الأرقام كلها مقروءة من الجداول لحظة إعداد الدراسة، وليست تقديرية.
> الغرض المعلن للنظام: **متابعة الخدمات اللوجستية للخامات الواردة** — التكاليف • المبيعات • الأرصدة • المراكب.

  ├─ group_desc  = "الــــــــــذرة"

## 4) 🎯 الجسر الحقيقي بين العالمين — **بالكود**

الربط الصحيح والدقيق موجود ومُتحقَّق منه:

```
items.group_code  ═══  contract_items.code  ═══  contract_balances.item_code
      1001               (1001..1033, 2001..2027, 3001..3007, 4002..4005, 5001..5002)
```

- أصناف النظام كودها موجود كمجموعة في `contract_items`: **64 مُطابق**، و**4 غير موجود** (`1028`, `2022`, `2025`, `3002`).
- **169 مجموعة أصناف** ليس لها كود في `contract_items` (طبيعي: ليست كل المجموعات خامات/إضافات متعاقدة).
- `contract_balances`: **37 كوداً** كلها موجودة في `contract_items`، و**36** منها موجودة كمجموعة `items.group_code`.

**ملاحظة حاسمة:** الربط لا يصحّ بالأسماء — الأسماء تختلف شكلاً بين الجداول:

| الكود | `contract_items.name` | `contract_balances.item_name` |
|---|---|---|
| 1001 | الــــــــــذرة (بمدّة) | الــــــــــــــــــــــــذرة |
| 1005 | دى جى اس | DDGS |
| 1006 | دوار الشمس | كسب دوار الشمس 36% |
| 2001 | الايثين | لاثين |

⇒ **الكود هو الحقيقة، والاسم للعرض فقط.**

### ب) المراجع — **مبعثرة وتخزّن أسماءً لا أكواداً** ⚠️

| الحقل في التسجيل | يخزّن | الجدول المرجعي | حالته | التطابق |
|---|---|---|---|---|
| `supplier` | **اسم** المورد (كارجيل, AMAGGI…) | `contract_suppliers` (S001..S014) | مختلط | بالاسم |
| `source_country` | **اسم** الدولة (برازيلى, امريكى…) | `contract_countries` | **فارغ** — البيانات في `contract_suppliers` (C001..C008) | بالاسم |
| `contracting_company` | **اسم** الشركة (الواحة للأعلاف…) | `contract_companies_internal` (1001..) | سليم | بالاسم |
| `arrival_port` | **اسم** الميناء المصري (ميناء برج العرب…) | داخل `contract_suppliers` (PN001..PN004) | — | بالاسم |

**مشكلة `contract_suppliers`:** جدول واحد يخلط **ثلاثة** أنواع (مورد `S*` + دولة `C*` + ميناء `PN*`)، وفيه **صفّان بعنوان عمود** (`كود المصدر`/`اسم المصدر`, `كود ميناء الوصول`/`اسم ميناء الوصول`).
**مشكلة `contract_ports`:** يحمل موانئ **المصدر/التصدير** (SAO LUIS, ITAQUI…) — وليس موانئ الوصول المصرية.

### ج) تصنيف التسجيل يخزّن **الاسم حرفياً** مطابقاً لـ `contract_items.name`

`الصويا (112) • الــــــــــذرة (26) • دى جى اس (9) • دوار الشمس (7) • البذرة (6)` — أي أن حلّ التصنيف = اسم ← كود عبر `contract_items`.

## 7) التكرار واللبس (نقاط تحتاج توحيداً)

1. **مراجع مبعثرة:** `contract_suppliers` يخلط مورد+دولة+ميناء، مع صفوف عنوان؛ و`contract_countries` فارغ؛ وموانئ الوصول داخل `contract_suppliers` بينما `contract_ports` لموانئ المصدر.
2. **الأسماء مكرّرة بشكل غير موحّد:** نفس الصنف باسم مختلِف في `contract_items` / `contract_balances` / `items.group_desc`.
3. **الحقيقة موزّعة:** التصنيف مذكور **بالاسم** في التسجيل/التفصيل، و**بالكود** في الأرصدة — فيتفرّق التصنيف الواحد.
4. **الملفات اليومية:** نفس الحركة قد تتكرّر داخل الملف الواحد (صفوف متطابقة فعلاً) — الاستيراد نفسه **متكرّر الأمان** (يحذف صفوف الملف قبل إعادة الإدراج)، فلا تكرار ناتج عن إعادة الاستيراد.
5. **عالمَان منفصلان:** منظومة العقود (`contract_*`) لا تتصل بالنظام العام (`items/movements/sales/balances`) إلا عبر الجسر بالكود — ولا يوجد ربط مُفعَّل فعلاً بعد.

## 8) مقترح التوحيد — «بيانات واحدة، محور واحد» بلا تكرار

### 8.1 المحور الأوحد للتصنيف (Canonical Spine)

جدول/عرض أبعاد واحد `dim_class` مفتاحه **كود واحد ثابت في كل المراحل**:

| الحقل | المصدر | الاستخدام |
|---|---|---|
| `class_code` | `contract_items.code` = `items.group_code` | **المفتاح الموحّد في كل المراحل** |
| `class_name` | `contract_items.name` (أو `items.group_desc`) | العرض |
| `direction` | `contract_items.direction` | خامات / إضافات / أخرى |
| `erp_class_code` | `items.class_code` (101/102/…) | تصنيف النظام |
| `erp_class_desc` | `items.class_desc` | خامات / إضافات / علف … |
| `erp_items_count` | عدّ `items` حيث `group_code=class_code` | الربط بالنظام العام |

**القاعدة:** كل مرحلة تُخزّن **الكود** (أو تُحلّله فوراً إلى كود) — لا اسم نصي حر:
- `contract_registrations.classification` (اسم) ← يُحلّ إلى `class_code` عبر `contract_items.name`.
- `contract_details.classification` ← نفس الحل.
- `contract_balances.item_code` ← كود مباشر.
- `items.group_code` ← كود مباشر.

### 8.2 توحيد المراجع (بلا تكرار)

فصل `contract_suppliers` إلى ثلاث قوائم نظيفة بمفتاح كود، وإزالة صفوف العنوان:

| المرجع | المصدر | المفتاح |
|---|---|---|
| `contract_suppliers` (موردون فقط) | S001.. | `code` |
| `contract_countries` (دول) | C001.. | `code` |
| `contract_ports` (موانئ الوصول) | PN001.. | `code` |
| `contract_source_ports` (موانئ المصدر PX*) | PX001.. | `code` |

### 8.3 الغرض التشغيلي — دور كل جدول (لوجستيات الخامات الواردة)

| المحور | الجداول | المخرج |
|---|---|---|
| **التكاليف** | `borse` + `prices` + `daily_costs` + `contract_payments` + `contract_hedge` + `contract_roll` | تكلفة الوحدة، المسدَّد، الربط، أثر الرول |
| **المبيعات** | `sales` + `contract_external_sales` | قيمة البيع، «ما تم بيعه» بالكود |
| **الأرصدة** | `balances` + `contract_balances` | الرصيد، الاستهلاك، أيام التغطية |
| **المراكب** | `contract_details` + `contract_loading` + `contract_release` | مركب/تحميل/افراج/وصول |

## 9) الخلاصة التنفيذية

1. **الحقيقة واضحة ومُتحقَّقة:** المحور الصحيح = **الكود** (`contract_items.code` = `items.group_code` = `contract_balances.item_code`)، والاسم للعرض فقط.
2. **السليم:** `internal_no` (100%) • الجسر بالكود • تغطية `movements` (100%).
3. **يحتاج توحيداً:** المراجع (مبعثرة) • الأسماء (غير موحّدة) • التصنيف بالاسم في بعض المراحل.
4. **يحتاج استكمالاً:** `contract_countries` (فارغ) • `contract_external_sales` (فارغ ⇒ «مبيع» صفر) • `vessel_name/arrival/vessel_status` (70-90% فراغ) • `contract_balances` (لقطة واحدة) • 332 كوداً بلا تطابق.
5. **التقارير:** تقاريري المُضافة أُزيلت؛ الباقي = تقارير Power BI العشرة (كما هي) + تقارير النظام الأساسية.
